## v2.8.0（2026-10-06）

> **绑定账号额度耗尽时不再是一块没有解释的空面板**（[#25](https://github.com/dingminhua/dsh-connect-trae/issues/25)，报告人 JiewiW）。

### 新增

- **「刷新账号与 Token」现在会报告结果**：成功后显示「找到 N 个账号 · 仍绑定 X」，失败时显示原因。用户从此能区分「刷新成功但无变化」与「刷新失败」。
- **绑定账号额度耗尽且本机另有可用账号时，卡片给出明确提示并支持一键切换**（仅国内版）：
  - 仅当**已选账号自身额度为 0** 时才去查其他账号，账号健康时**不产生任何额外请求**；
  - 提示里带上可用账号的名字、产品与可用积分数，一键写入绑定并立即刷新；
  - 其他账号同样为空、或来自另一区域的，一律不提示——避免给出「切过去也用不了」或「数字不适用本区」的建议。
- **账号下拉显示可读的产品名**：`Trae` / `Trae 国际版` / `TRAE SOLO` / `TRAE SOLO 国际版`，取代原先裸露的 `cn` / `sg` / `solo` 标记——正是这个标记让报告人分不清哪个凭据来自已卸载的产品。

### 为什么不自动切换

账号选择是**持久化**的：插件不会因为某个账号额度用尽、或检测到另一个可用账号就自作主张替你切换（**换账号意味着换人计费**）。所以这里选择的是「明确告知 + 一键切换」，而不是静默改绑。

### 实现要点

- 新增只读的 `TraeCredentialStore.credentialOf(accountId)`：查某个**指定**账号的凭据而不改绑。原先只能靠切换绑定来读，而那会与共用同一 store 的在途聊天请求竞争，并持久化一次用户并未做出的选择。这个方法是纯查询：只读、无刷新副作用、`accountId` 不变。
- 探测其他账号的额度用一个**临时** usage client，并复用与绑定账号**完全相同**的 `toCredits`（Work/general 分桶），避免出现「提示里的数字和旁边显示的数字算法不一致」。

### 测试

- 全仓 419 → **423**：绑定账号为空时才出现替代账号；账号健康时**一次都不探测**（断言探测次数为 0）；同样为空、以及**跨区域**的账号既不被提示也不被探测；单个账号探测抛错时安全降级。
- **变异验证 3 次全部被抓**（永不触发探测 / 去掉「无额度」过滤 / 去掉区域限制）。
