## v2.14.0（2026-10-07）

> **积分浮层改为表格：本区域每个账号一行、只列通用积分、点行即可切换账号。**

### 新增

- **浮层改成表格**：表头「账号 | 通用积分」，**本区域有几个账号就显示几行**。
- **只列通用积分**，去掉 Work 积分栏——表格里两列数字是噪音，Work 积分也不参与消耗，明细去卡片看。
- **点行直接切换账号**：当前账号标记绿色圆点且**禁用**（点了是无效写入），其余行可点。刷新按钮保留在浮层里。

### 切换的正确性

`accounts` 是**共享字段**，卡片与这个表格是它的**两个写入者**。因此把 `configuredAccountsOf`（深解包 + 合并规则）从卡片私有**提到 `status-paths.ts` 共用**——两个写入者必须共用同一条合并规则。该规则本身是踩出来的：不解包会把 `{get()}` 引用散播进配置文档，**丢掉另一个区域的选择并泄漏函数**。

写入仍**读后校验**：`set()` resolve 不等于落库，读回不是目标值就报错。

### 新端点 `/plugins/dsh-connect-trae/account-credits`

返回本区域**每个账号的通用积分**。三个取舍：

1. **只在浮层打开时取**（每账号 1 次上游读）——5 分钟读数不按账号数量翻倍，与 `creditAlternatives` 只在余额归零时触发同一条原则；有测试锁住。
2. **不排除已选账号、不排除 0 余额**——`alternatives` 的排除是为「可切过去的账号」设计的，这张表是「这里有什么」的清单。
3. **读失败的账号仍在表里**（无数字）——面板的目的是看见有哪些账号并切过去。

### 测试

- 全仓 476 → **480**（客户端 4 例 + 宿主 4 例）。
- **变异验证 4+1 次全部被抓**。
- 顺带修复测试桩：此前对**所有** URL 返回用量文档，会把新端点的 `accounts` 填成 `[]`——测试会因**错误原因**失败。现已按 URL 分流。
