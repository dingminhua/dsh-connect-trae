# issue #95 诊断：输入框工具栏的积分读数与弹出浮层里的积分读数不同步

> issue：<https://github.com/dingminhua/dsh-connect-trae/issues/95>
> （「如图，弹出面板与输入框工具栏中积分读数不同步」）
> 诊断时间：2026-11-22　方法：读代码 + 在本机跑宿主已装插件的两条路由做对照 + 单元测试
> 状态：**插件缺陷（两个读数来自两次互不知情的读）**。本版让它们读同一个数。

---

## 0. 一句话结论

输入框工具栏上的积分读数来自**用量文档**（5 分钟轮询一次），浮层表格里的那一行来自**另一条
路由**（浮层打开时再读一遍）。两次读之间余额可能已经变了，于是同一个账号在屏幕上出现两个
数。

更要命的是第二层：**用量文档里的 `accountId` 与它携带的积分不是同一个账号**——前者取自账号
列表的 `selected`（保存的绑定），后者读自宿主真正计费的那个凭据。账号池开着时这两者不是同一
个账号，浮层于是把「工具栏那个数」放到了另一账号的行上。

修复一条规则：**一个账号、一个数、一次读。**

---

## 1. 现象

报告者的截图里，两处并排出现在同一屏：

- 输入框工具栏：`Trae CN · 2,531`
- 浮层表格里那个账号的行：`2,528`

浮层脚注还写着「最近刷新 21:47」——那是**工具栏那个数**的读数时刻，而不是表格里那一行的读数
时刻。也就是说：脚注在描述一个数，表格在显示另一个数。

（本仓库不落库任何真实余额，上面用的是 `tools/demo-accounts.ts` 里编造的形状：通用积分
`DEMO_CREDITS.general`，差值 3 与报告一致。issue 里的原始数字请看 issue 本身。）

---

## 2. 根因 A：两个读数来自两次互不知情的读

| 位置 | 数据来源 | 何时读 |
| --- | --- | --- |
| 输入框工具栏的读数 | `GET /plugins/dsh-connect-trae/usage`（用量文档里的 `credits.generalAvailable`） | 挂载时 + 每 5 分钟一次 |
| 浮层表格的行 | `GET /plugins/dsh-connect-trae/account-credits`（逐账号再读一遍余额） | **浮层打开时** |

两者之间**没有任何同步**：浮层打开时只读逐账号那条路由，不重读用量文档。于是

- 工具栏的数 = 上一次轮询时的余额；
- 浮层的数 = 打开那一刻的余额。

报告者那次差 3 分：轮询之后又跑了一轮对话，扣了 3 分。**这不是精度问题，是两个时刻被当成
同一个数展示**——而报告者没法知道这一点，只能看到「两个数不一样」。

顺带一处次要的错位：浮层脚注的「最近刷新」用的是 `fetchUsage` 记下的时刻，描述的是**工具栏
那个数**，却摆在**表格**下面。

## 3. 根因 B：文档里的 `accountId` 与它携带的积分不是同一个账号

`src/web-status.ts` 组装用量文档时：

```ts
const account = {
  accountId: accounts.find(item => item.selected)?.id ?? '',   // ← 账号列表里「保存的绑定」
  accountName: credential.accountName ?? credential.userId,     // ← 真正被计费的凭据
  tokenExpiresAtMs: credential.expiresAtMs,
  ...
}
// ……
const credits = toCredits(snapshotResult.value)                  // ← 真正被计费的凭据
```

（上面两处是**节选与改写**，不是逐字引用：真实代码在 `Promise.allSettled([client.snapshot(),
…])` 之后才取 `snapshotResult.value`，见 `src/web-status.ts`。）

`client` 读的是 `store.resolve()`，而 `resolve()` **认账号池的轮换**：账号池开着时，它是
「下一个请求会由谁计费」的那个账号（池的选择由 `applyPoolSelection()` 施加，跑在**组装池小节**
的时候）。账号列表里的 `selected` 却是**保存的绑定**，不认轮换。

**顺序本身也是坑**：池小节在文档的**后半段**才组装，所以「把 `accountId` 改成凭据自己的 id」
这一改本身**并不够**——那一刻读到的仍是请求刚开始时轮换指向的账号，而积分读的是池选完之后那个
账号。身份必须在**池说话之后**再读一次。

两者不同时，文档就变成一件**同时描述两个账号**的东西：id 是 A 的，名字、到期时间、积分是 B 的。

本机实测（账号池开着、两个成员都在池里）：

```text
$ curl -s "http://127.0.0.1:61891/plugins/dsh-connect-trae/usage?region=cn" | jq '{accountId, accountName, credits: .credits.generalAvailable}'
{ "accountId": "<绑定账号>", "accountName": "<池选中账号>", "credits": <池选中账号的余额> }

$ curl -s "http://127.0.0.1:61891/plugins/dsh-connect-trae/account-credits?region=cn" | jq '.accounts[] | {id, selected, generalAvailable}'
{ "id": "<绑定账号>", "selected": true,  "generalAvailable": <绑定账号的余额> }
{ "id": "<池选中账号>", "selected": false, "generalAvailable": <池选中账号的余额> }
```

**浮层那一行（带绿点、带 `selected`）是绑定账号，它的余额与工具栏上那个数不是同一个账号的
余额。** 浮层自己的代码又用 `selected` 找「当前行」，于是把工具栏的数安到了另一账号的行上。

没有账号池时，`resolve()` 就是绑定账号，A、B 合一，上面的错位看不出来——所以这不是「开了号池
才有」的毛病，而是**平时不显形、开了就显形**。

## 4. 修复

### 4.1 宿主：文档必须说明它读的是哪个账号

`src/web-status.ts`：**先组装池小节**（池的选择在那里跑），**再**从 store 读一次身份。于是 id、
名字、到期时间、积分**说的是同一个账号**——池挑了谁就是谁。

账号列表里的 `selected` 保持原义——它是保存的绑定，卡片「保存当前选中账号」读的是它。

### 4.2 客户端：一个账号、一个数、一次读

`src/client/ComposerPoints.tsx`：

1. **当前行 = 正在计费的那个账号**。两条规则、同一个答案：
   - **账号池小节里的 `current` 标记**（「当前计费：X」那个口径）——账号池的选择在文档读积分
     **之前**就跑了，所以这个标记指的正是文档携带余额的那个账号；
   - 文档自己的 `accountId`（它读的是哪个凭据）。

   池的标记排在前面是有意的：它是**即使插件两半不同步也仍然正确**的那一条——客户端包是从磁盘
   提供的，浏览器刷新可能拿到新的客户端，而宿主进程里跑的还是旧的宿主模块。`accountId` 是宿主
   不提供账号池小节时的兜底。表格的 `selected`（保存的绑定）排在最后。
2. **当前行的数字 = 工具栏那个数字**（文档的 `credits.generalAvailable`），不再另读一份；
   其它账号的行仍用逐账号那条路由的余额——文档只知道一个账号；
3. **浮层打开时重读用量文档**：打开浮层就是「现在还剩多少」的提问，于是工具栏的数也在那一刻
   变新，两个数从此取自同一时刻；
4. **那次重读不会被在途的轮询读吞掉**：原来的 `inFlight` 是布尔量，轮询正在读时浮层那次读会被
   **直接丢掉**——浮层于是又读到一份比工具栏新的余额，正是本版要消掉的不一致。现在在途的读
   被**等待**，而不是被跳过；
5. **账号池在挑人时，浮层不再提供「切换账号」**：点行写的是**保存的绑定**，而池开着的时候
   计费账号是池挑的——那个按钮按下去什么也改不了（账号池卡片本身也是这么处理的：池开着时
   它不画手动选择器，只写「当前计费：X」）。浮层里改为不画按钮、保留名字与圆点，并在底部
   写明原因。

## 5. 验证

新增 `tests/composer-points.spec.tsx` 6 例 + `tests/web-status.spec.ts` 2 例（先红后绿）：

| 用例 | 钉住的事实 |
| --- | --- |
| 工具栏的数与表格那一行必须相等 | 同一账号的余额不许出现两个数 |
| 当前行是**正在计费**的账号，不是表格 `selected` 说的 | 号池轮换时不会把数安到别的账号行上 |
| 池的「当前计费」标记优先于文档的 `accountId` | 插件两半不同步时也不会安错行 |
| 打开浮层会重读用量文档 | 浮层打开那一刻，两处读的是同一个时刻 |
| 轮询在途时那次重读**不被吞掉** | 在途的读被等待，而不是被跳过 |
| 池在挑人时不提供切换按钮 | 不画一个按下去什么也改不了的控件 |
| 文档的 `accountId` 是它**读**的账号 | 文档不会再同时描述两个账号 |
| 池在组装中途挑了另一个账号时，文档报的是**池挑的那个** | 身份在池说话**之后**才读 |

（`tests/issue77-fast-first-paint.spec.ts` 的一处计数断言随「身份读两次」更新：首屏读的仍是
**本地**凭据、`resolve()` 仍是 0 次——首屏不许由一次令牌刷新决定何时出现，这条没动。）

## 6. 已知边界

- **「最近刷新」描述的是用量文档的读数时刻**，也就是工具栏那个数（以及当前行那一格）的时刻。
  浮层里**其它**账号的余额是逐账号路由另外读的，两者相差一两秒；它们本来就不是同一个账号，
  差一个时刻不影响任何一个数。
- **账号池开着时，浮层不再能切换绑定账号**。绑定在池里其实是兜底（成员全都不可用时才轮回
  绑定），要换绑定请到设置页——那里的账号池卡片同样在池开着时不提供手动选择器。
- **浮层的行仍然列出本区域的全部账号**（不只是池成员），非池成员的余额照常显示，只是那个
  账号此刻不在计费。
