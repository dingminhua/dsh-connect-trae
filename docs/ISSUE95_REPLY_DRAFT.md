谢谢报告——这个现象是对的，而且根因不止一处，其中一处比「刷新时间差」更值得说。

## 一、先说你截图里那一对数字：它们来自**两次互不知情的读**

输入框工具栏上的读数，来自**用量文档**（5 分钟轮询一次）；浮层表格里那一行，来自**另一条
路由**（浮层打开时把每个账号的余额再读一遍）。这两次读之间**没有任何同步**——浮层打开时并
不重读用量文档。

所以你看到的就是同一个账号在两个时刻的两个余额：你截图里浮层脚注写的「最近刷新 21:47」，
其实是**工具栏那个数**的读数时刻，而表格里那一行是**打开浮层那一刻**重新读出来的。中间那轮
对话扣掉的积分，就落在这个差里。

顺带说，脚注那句「最近刷新」描述的也是工具栏那个数，不是表格那一行——这本身也是一处摆放错
位，一并改了。

## 二、还有一层：开着**账号池**时，两处说的甚至不是同一个账号

这条更隐蔽，我是在本机把两条路由对着打才发现的：

- 用量文档里的 `accountId` 取自账号列表的 `selected`，那是**你保存的绑定账号**；
- 文档里的积分却是读自宿主**真正计费**的那个凭据——账号池开着时，那是**池挑出来的**账号。

也就是说，那份文档会同时描述两个账号：id 是 A 的，名字、到期时间、积分是 B 的。浮层自己的代码
又用 `selected` 去找「当前行」，于是把工具栏上的那个数，安到了**另一个账号**的行上。

本机实测（池开着、两个成员都在池里）的对照，形态如下：

```text
usage         → { accountId: <绑定账号>, accountName: <池选中账号>, credits: <池选中账号的余额> }
account-credits → [ { id: <绑定账号>,     selected: true,  generalAvailable: <绑定账号的余额> },
                    { id: <池选中账号>,   selected: false, generalAvailable: <池选中账号的余额> } ]
```

没有账号池时这两者是同一个账号，所以平时看不出来；开了号池才会显形。

## 三、修复：一条规则——**一个账号、一个数、一次读**

1. **用量文档必须说明它读的是哪个账号**：账号池的选择是在**组装池小节**时跑的，所以文档改成
   **先组装池小节、再读身份**——id、名字、到期时间、积分说的是同一个账号（池挑了谁就是谁）。
   账号列表里的 `selected` 保持原义（它是保存的绑定，卡片的「保存当前选中账号」读的是它）。
2. **工具栏那个数就是浮层当前行的数**：浮层里「当前」那一行不再另读一份余额，直接用工具栏
   旁边那个数——同一个账号的余额不许在屏幕上出现两个值。其它账号的行照旧各自读自己的余额。
3. **打开浮层会重读用量文档**：打开浮层就是「现在还剩多少」的提问，于是工具栏的数也在那一刻
   变新，两处从此取自同一时刻。
4. **当前行认的是「正在计费」的那个账号**，不是表格里的 `selected`——池挑了谁就标谁，和账号池
   卡片里的「当前计费：X」是同一个口径。
5. **打开浮层时那次重读不会被在途的轮询读吞掉**：原来轮询正在读时，浮层那次读会被直接丢掉——
   浮层于是又读到一份比工具栏新的余额，正是这个 issue 要消掉的那种不一致。现在在途的读被
   **等待**，不是被跳过。

## 四、修完之后你会看到什么

- 浮层里当前那一行的数字，和输入框工具栏上的数字**完全一致**；
- 打开浮层时，工具栏上的数字会跟着刷新一次（你可能看到它从旧值跳到新值——那是它在追赶当下，
  不是又错了）；
- 池里当前计费的那个账号会被标上圆点。

**一处和你预期可能不同**：**账号池开着的时候，浮层不再提供「点行切换账号」**。因为池开着时
计费账号是池挑的，点行写下的绑定并不决定谁计费——那个按钮按下去什么也改不了，所以不画了，
改为在浮层底部写明「账号池正在挑选计费账号」。账号池卡片本身也是同一套做法（池开着时它只写
「当前计费：X」，不画手动选择器）。要手动指定账号，请到设置页处理。

## 五、验证

新增 8 例回归测试（先写会红的）：工具栏与浮层当前行必须同数、当前行认「正在计费」的账号、
打开浮层会重读用量文档、**轮询在途时那次重读不被吞掉**、池挑人时不提供切换按钮、用量文档的
`accountId` 是它**读**的账号、「池的当前计费标记优先于文档的 id」（插件两半不同步时也不会安错
行），以及「池在组装中途挑了另一个账号时，文档报的是池挑的那个」。
