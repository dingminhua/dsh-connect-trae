## v4.17.0（2026-11-09）

> **自动刷新不再是写死的了 —— 卡片和输入框读数共用同一个节奏，默认 5 分钟。**

改动前，插件对**同两条只读上游路由**用了**两个硬编码节奏**：卡片每 60 秒重读一次用量文档，输入框读数每 5 分钟一次。取哪个取决于你正好在看哪个界面，两个都改不了。而每次用量读取是**两次上游请求**，所以「正在看卡片」这件事本身就悄悄把后台流量翻了几倍。

现在是一个设置：**设置 → Trae → 能力 → 自动刷新**，可选 **1 / 5 / 10 / 30 / 60 分钟**，**默认 5**。

### 新增

- **自动刷新间隔**（`Config.refreshIntervalMinutes`，默认 `5`）
  - **默认选 5 而不是保留卡片的 60 秒**。5 分钟正是输入框读数原本的节奏，所以升级不改变任何人的观感；卡片的 60 秒被拉到同一个值上，也是 README 一直写的数字。
  - **整个插件一个值，不是每个面板一个**。它配的是插件的后台噪声，不是某个区域的数据：两处打的是同两条路由、同样的代价。按面板存会让同一块屏幕出现两个节奏，而这正是本版要消灭的东西。
  - **改动即时生效**。旧定时器先被清掉、在途请求被中止，再按新间隔重建 —— 不会留下两个循环并跑（那会让上游请求翻倍，而界面上完全看不出来）。
  - **间隔越短请求越频繁**，所以下限是 1 分钟；这里**不消耗积分**，每次刷新只是两次只读请求。

- **写入与读取都做了防护**，因为这一项设置一旦错了不会有任何报错，只有「数字悄悄变旧」：

  | 环节 | 做法 | 不做会怎样 |
  | --- | --- | --- |
  | schema | 只接受五个值 | 手改文件写个 `7` 会被接受，得到一个没人选过的节奏 |
  | 读取 | 集合外一律回落默认 | 认不出的值让刷新**静默停止** |
  | 写入 | 读回校验，比的是解析后的分钟数 | 选择器显示新值而定时器还是旧的 |
  | 定时器 | 间隔进 effect 依赖，cleanup 先清旧、中止在途 | 改一次间隔就多一个循环并跑 |

- **选项列表是共享常量**，schema 与下拉框都从它渲染：两处各写一份字面量，就会出现「下拉给得出、写入被拒绝」的选项。

### 修复

- **输入框读数补了一次自己的设置订阅**。它挂在 gate 之下，而 gate 订阅的是自己的两个开关 —— 子组件不会因为父组件订阅了而重渲染。没有这次订阅，改了间隔要等到下一次无关渲染才生效。

### 测试

- 新增 `tests/refresh-interval.spec.tsx`（16 例）：读取器的默认 / 全集 / 回落 / `{get()}` 实时引用；schema 接受五个值、拒绝 `7` 与 `0`；选择器在「能力」分栏、显示存储值、只写一个字段、只读时拒写；**卡片按存储间隔读**（存 10 分钟时，1 分钟处零请求、10 分钟处恰好一次）；**改间隔会替换定时器**（旧 60 分钟 → 新 1 分钟，一分钟处恰好一次读）；**输入框读数用同一字段**（1 分钟处就有读，不等旧的 5 分钟常量）。
- **变异验证 4 次全部被抓**：卡片定时器改回固定 60s、输入框读数改回自己的常量、读取器接受任意数字 —— 另有一次改动由既有 `card-styles` 的「每个渲染出来的类都要有规则」守卫抓出。
- 全仓 **113 个文件 / 1462 条测试**通过，两个 tsconfig 分别 typecheck 通过，构建通过，`verify:privacy` 17 项无跳过。

### 顺带

`styles.ts` 的注释里曾写了一个反引号包住的类名 —— 那个模板字符串会当场截断，整份样式表变成语法碎片，而 typecheck 与 build 都不报错。`card-styles` 的「顶层语句只能是变量声明」守卫当场抓到，改回普通文字。这个坑本仓库文档里已经记过一次。
