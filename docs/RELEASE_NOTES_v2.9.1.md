## v2.9.1（2026-10-07）

> **修复：积分行默认不显示，而它的开关在部分宿主上根本打不开。**

### 问题

2.9.0 把侧边栏积分行做成了 **opt-in**（`showPointsInMainUi` 默认 `false`），开关只放在插件卡片里。这在部分宿主上等于**功能不存在**：

- 用户装了 **dshmarket**，插件页默认停在市场的 tab，而市场 UI **完全不渲染插件自带的配置卡片**（在其客户端 bundle 里搜 `plugins.row.config` / `plugins.bundle.config`，**0 处引用**——它只注册自己的卡片，key 是 `dshmarket`）。
- 于是积分行被 Gate 挡住不渲染，而唯一能打开它的开关在用户到不了的页面里：**既看不到功能，也找不到开关**。

根因是把「可关闭」实现成了「默认关闭」——原本的要求是「**加这个显示**，同时给不想显示的人一个关闭开关」，即**默认显示 + 可关闭**。

### 修复

- **`showPointsInMainUi` 默认改为 `true`**（opt-out）：侧边栏底部直接显示通用积分。
- **关闭开关移到积分行自己身上**：行右侧的 `×` 点一下隐藏；隐藏后**同一位置留一个极小的「积分」按钮**，一点即恢复。
  - 两个控件写的是**同一个字段**，与插件卡片里的复选框永不冲突。
  - 关键是**控制入口与功能渲染在同一处**：宿主能画这一行，就等于用户能控制它，不再依赖任何设置页。
- 侧边栏收起（56px 导轨）时仍然整行不渲染：收起态塞不下标签+数值+按钮，会变成「积…」。

### 兼容性

- 之前**明确关闭过**该开关的用户不受影响（显式 `false` 仍是关闭）。
- 「字段缺失」现在按**开启**处理（原先按关闭），所以升级后会直接看到积分行。
- 插件卡片里的复选框**保留**，在能渲染卡片的宿主上依然可用。

### 测试

- 全仓 433 → **435**：新增「默认即显示」「关闭后留下可恢复的入口」「行内关闭按钮写入共享字段」；并把原「关闭时不渲染任何 DOM」的用例改写为**「关闭时仍留一个可操作入口」**——那条旧断言正是把这次的问题固化下来的地方。
- **变异验证 2 次全部被抓**（改回「必须显式 true」→ 1 例失败；关闭时不渲染入口 → 1 例失败）。
