## v2.13.3（2026-10-07）

> **把「显示积分」开关加回设置卡片，这次控制的是输入框的积分读数。**

### 背景

2.13.0 移除侧边栏积分行时，卡片里那两处「在DSH主界面显示积分状态」复选框被一并删除，理由是输入框读数会自动出现、不需要开关。

这个判断是错的：**输入框工具栏是与 shell 自己的权限/专家/模型控件共享的一行**，那里的读数应当由用户主动开启。2.13.0–2.13.2 之间它无条件渲染。

### 变更

- **恢复开关**：卡片顶部一个复选框「在输入框工具栏显示积分读数」，带说明性 tooltip。
- **字段复用 `showPointsInMainUi`**：已经把它设为 `true` 的用户升级后**读数直接保留**，不会发现它悄悄关掉。
- **默认关闭**。字段为 `true` 的用户保持显示；字段缺失/为 `false` 的用户需要勾选开启（他们在 2.11.0–2.13.2 期间曾无条件看到读数——**这是行为变更**，见下）。
- 开关是**唯一写入者**，写入沿用卡片其余设置的「写后读回校验」。

### 行为变更提示

2.11.0 起读数**无视**该字段、始终渲染；现在它重新遵守这个字段表达的用户意图。因此：

| 你的 `showPointsInMainUi` | 升级后 |
| --- | --- |
| `true`（曾开启过旧侧边栏行） | **保持显示**，卡片里复选框为勾选 |
| 缺失 或 `false` | 不再自动显示；需要到卡片勾选开启 |

### 实现

- `ComposerPointsGate` 接收注入的 `settingsScope` 并订阅，只在 `showPointsInMainUi === true` **且**当前模型属于本插件（`trae`/`trae-global`）时渲染。任一条件不满足即零 DOM、零请求。
- 客户端入口把 `settingsScope` 一并注入 `conversation.input.left` 槽位。

### 测试

- 全仓 461 → **466**。
- **刻意修正一处会“假通过”的测试**：`另一个供应商时不渲染` 与新开关叠加后会因「开关关闭」而非「供应商不匹配」通过，断言即失去意义；现在显式传入已开启的 scope。
- 新增卡片测试直接点击真实复选框并断言 `scope.set('showPointsInMainUi', …)`，控件按**标签**选取而非位置。
- **变异验证 4 次全部被抓**。
