## v2.13.5（2026-10-07）

> **修复：输入框积分读数完全没有样式——丑按钮方框、点开没有账号面板，是同一个原因。**

### 根因

**composer 的样式根本没有被注入。** 2.12.0 把 `.dsm-trae-composer-*` 写进了 `TRAE_SIDEBAR_CSS`，而 2.13.0 移除侧边栏时删掉了整个常量——**连带删掉了 composer 的样式**。此后 2.13.0–2.13.4 期间：

- 触发器 → 退回浏览器**默认按钮样式**（截图里那个带边框的方块）；
- 浮层 → 没有 `position: fixed`，内联的 `left/top` **被忽略**，它落进文档流、不在触发器附近——所以**看不到账号面板**。

两件事是同一个原因。

### 修复

- 新增**独立**的 `COMPOSER_POINTS_CSS`，由 `ComposerPoints` 在**模块加载时注入 `<head>`**（与卡片同一套幂等模式，重复渲染不重复插入）。
- **触发器改为纯文本外观**：`border:0`、`background:transparent`、`color/font: inherit`——静止时与周围文字完全一致，只有 `padding` 提供点击区域，悬停才有底色提示。即「保留之前的样式，只加一个点击区域」。
- **浮层恢复 `position: fixed` + `z-index`**，材质取自 shell 的 `--dsw-*` 令牌，跟随主题。
- 浮层刷新按钮**不再依赖 `.dsm-btn`**（该类只随卡片注入，composer 拿不到）。

### 防复发

新增 `tests/composer-styles.spec.tsx`（5 例）：

- 组件确实在 `<head>` 写入样式标签，且**重复渲染只写一次**；
- **渲染的每一个 `dsm-*` 类，在注入的样式表里都必须有规则**；
- 浮层规则必须含 `position:fixed`；
- 触发器必须 `border:0` + 透明背景，且有 `:hover`。

**变异验证 4 次全部被抓**（构造 style 不挂 head / 触发器规则丢失 / 浮层改 absolute / 触发器改回边框），各 1 例失败。

jsdom **不做布局、不参与层叠**，所以「样式被整个删掉」在原有 460+ 测试里一条都不会红——因此这类守卫必须是结构断言。
