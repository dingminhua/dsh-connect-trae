## v2.7.2（2026-10-05）

> **补完 [#23](https://github.com/dingminhua/dsh-connect-trae/issues/23) 的确定性。** 2.7.1 修好了 Max 档随机丢失，但**在 max 相等时仍保留先到者**，于是「默认 dev 窗口」还会随分组顺序漂移。

### 修复

- **择强规则改为逐级比较到底**：① 带 Max 优先 → ② Max 更大者胜 → ③ **max 相等（或都无 Max）时比 dev，取更宽者** → ④ 完全相等才保留先到者。
  - 报告人 JiewiW 在 Windows 复测 2.7.1 时发现：`glm-5.2` 的 `chat_v3` 行是 `dev=116000/max=1000000`，而 `solo_agent_remote`/`solo_agent` 行是 `dev=200000/max=1000000`——max 相同，谁先到就取谁（本机 CN 30 个模型里 9 个如此）。
  - **影响面**：配置了 1M 预算的模型最终仍恒为 1M，所以不易察觉；但**未配置预算的模型的默认窗口**会一次一变，而默认窗口决定 DSH 的显示与压缩基准——正是 #23 要消除的同一类缺陷。
  - **实测（本机 CN，连刷 8 次）**：修复后**整目录指纹 8/8 完全一致**（含 30 个模型各自的 dev 与 max）；`glm-5.2` 稳定为 `dev=200000 / max=1000000`。修复前同一份数据的两种分组顺序分别得到 `116000` 与 `200000`。

### 测试

- 全仓 417 → **419**：新增「max 相等时按 dev 取宽且与顺序无关」「带 Max 的行仍胜过 dev 更宽的无 Max 行」；并把原有「6 种分组排列」用例的数据改成**「max 相等但 dev 不等」**——正是报告人指出的形态。该用例此前只覆盖 dev 相同的情形，因此没能发现这个问题。
- **变异验证 2 次全部被抓**（退回「max 相等即保留先到者」/ 去掉「带 Max 优先于 dev 更宽」）。
