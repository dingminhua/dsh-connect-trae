## v2.9.0（2026-10-06）

> **可选：在 DSH 主界面侧边栏常驻一行通用积分**（[#26](https://github.com/dingminhua/dsh-connect-trae/issues/26)，**实现由报告人 JiewiW 提交**）。

### 新增

- **侧边栏积分行**（开关「在 DSH 主界面显示积分状态」，**默认关闭**）：
  - 在**左侧边栏底部**（工作区列表下方、设置上方）常驻一行「通用积分：<数值>」与「刷新」按钮；`title` 显示最近刷新时间；
  - 抓取失败**保留上一次数值**并提示失败；刷新进行中忽略重复点击；
  - 开关关闭时**不渲染任何 DOM**（不是隐藏），因此不产生任何请求；关闭开关或插件卸载即清除定时器并中止在途请求；
  - 开启后**先立即抓取一次，完成后再启动 5 分钟周期**的定时器，不叠加。

### 合入时相对贡献者实现的三处调整

1. **数字口径：`credits.generalAvailable`（通用积分），不是 `credits.available`。**
   `available` 是上游汇总（`summary.totalAmount - consumedAmount`），而卡片展示的是按额度包分出的 Work / 通用两桶；汇总**不保证**等于任一桶。一个用户在侧边栏找不到对应数字的余额，比没有数字更糟。通用桶也正是 SOLO 聊天路径消耗的那个。
2. **轮询 60s → 5 分钟。** 卡片的轮询本身就是 60s，而每次 usage 读取会打**两个**上游请求；积分以「模型调用」而非秒为单位变化，60s 的边际价值很低。
3. **侧边栏收起时整行不渲染。** 宿主 CSS 并**不会**在收起时隐藏底部区域，而是把它压成 56px 居中窄条；标签 + 余额 + 按钮塞进 56px 会被裁成「积…」。而**收起正是长时间工作的常态**——这个功能最需要成立的时刻不能是它最坏看的时刻。提前退出也意味着收起期间不启动抓取循环。

### 测试

- 全仓 423 → **433**：移植贡献者的 7 例（开关默认关闭/持久化/读回/回显；挂载即抓取、首次抓取后启定时器、卸载即清除；失败保留上次数值；进行中点击被忽略；Gate 关闭时零 DOM），并新增 3 例锁定上述调整。
- **两处测试加固**（都是可能被悄悄破坏的地方）：
  - 贡献者的 fixture 让 `available` 与 `generalAvailable` **恰好相等**，所以换成哪个字段测试都过——正是能悄悄退回汇总口径的盲区。现已让两者**不相等**。
  - `card-region-switch` 原按下标取「前两个 checkbox」，新开关让卡片变成三个，改为**按 aria-label 精确匹配**区域开关。
- **变异验证 3 次全部被抓**（收起态不再退出 / 取字段改回 `available` / 轮询改回 60s）。
