## v2.11.0（2026-10-07）

> **新增：在输入框工具栏显示「Trae CN 积分」——只在当前模型属于本插件时出现。**

这样两个连接器插件不再争同一个位置：侧边栏底部是**一条共享的根级行**，两个插件各放一行就会互相挤压（实测结果见 2.10.3：本插件的行被压成裁切的「Tr」）；而输入框工具栏是**按会话、按供应商**的，同一时刻只有一个插件的额度是相关的。

### 新增

- **输入框工具栏的积分读数**（`conversation.input.left` 槽位，位于「专家」与模型选择器之间）：
  - 显示 `Trae CN 积分 <数值>` + **一个刷新图标按钮**。不占标签、不放第二个按钮——这一行与权限/专家/模型控件共享，必须保持窄。
  - **按供应商显示**：读宿主自己的 `modelSelection` 投影，只有当前模型的 provider 是 `trae` / `trae-global` 时才渲染；选其它供应商的模型时**完全不渲染**（无 DOM、无请求）。
  - `next` 优先于 `lastUsed`：已经切换但尚未发送的选择，才是输入框上显示给用户看的那个。
  - 5 分钟自动刷新；点击图标手动刷新；失败保留上次数值。
  - 数值为**通用积分**（`credits.generalAvailable`），与卡片上那一栏口径一致。

### 为什么用投影而不是插件自己的状态

`modelSelection` 投影是**模型选择器写入、下一次请求实际使用**的那个值，因此读数不可能与生效的模型不一致。

### 为什么改到输入框工具栏

侧边栏底部（`sidebar.footer.action`）是**根级共享行**：按横向 flex 排列 shell 自己的按钮与所有插件的贡献，两个插件各占一行就会互相挤压。输入框工具栏是**会话作用域**且能读到当前供应商，因此天然只显示相关的那一个——这是「各自占位置」问题的**结构性解法**，而不是把行做窄一点。

### 测试

- 全仓 435 → **446**（+11）：`selectedProviderOf` 的四种退化输入；**另一个供应商时零渲染零请求**；投影未就绪时零渲染；`trae` → CN、`trae-global` → 国际；**直接以非本插件 provider 渲染组件时零渲染零请求**；读数取通用积分而非汇总；行内**只有 1 个按钮**且是刷新图标。
- **变异验证 3 次全部被抓**：忽略 `next` 只看 `lastUsed` → 1 例失败；改回汇总口径 `available` → 2 例失败；去掉组件内层的归属守卫 → 1 例失败。
  - 其中「去掉归属守卫」最初**没被抓到**：外层 Gate 已过滤，组件内层守卫是纵深防御，两条都被删也不会红。为此补了一条**直接以外部 provider 渲染组件**的用例。
