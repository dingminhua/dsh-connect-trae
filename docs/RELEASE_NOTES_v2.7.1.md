## v2.7.1（2026-10-05）

> **修复「Max 档随机丢失、同一模型的上下文窗口在多次刷新之间漂移」**（[#23](https://github.com/dingminhua/dsh-connect-trae/issues/23)，报告人 JiewiW）。

### 修复

- **跨货架去重改为「保留容量最强的行」**：
  - Trae 的 remote 目录**按 function 分组**，同一个模型出现在多个组里，而**各组报告的容量不同**。实测同一次响应中 `Doubao-Seed-2.1-Pro` 的各组值：`116000`/无 Max、`256000`/无 Max、以及 `256000`/**`1000000`** 三种。
  - 而**分组顺序每次调用都不同**（连打 5 次得到 5 种顺序）。此前的去重是「第一次遇到就锁定」，于是同一模型的发布容量取决于哪一组恰好先回来——`116000`、`256000`、带 Max 三种结果随机出现。
  - 后果不只是显示：`maxContextWindow` 缺失时，你在卡片上选择的 1M 预算会被**静默忽略**，DSH 会在远早于预期的位置反复压缩。
  - 现在按「带 Max 优先 → Max 更大者胜 → 都无 Max 取更宽 dev 窗口」择强，结果**不再依赖分组顺序**。
  - **实测对比**（本机 CN，连打 6 次实时目录，同一预算配置）：

    | | 修复前 | 修复后 |
    | --- | --- | --- |
    | `Doubao-Seed-2.1-Pro` | `116000/无`、`256000/1000000`、`256000/无` **三种漂移** | 6/6 稳定 **`256000/1000000`** |
    | 目录中带 Max 档的模型数 | **11 → 26 随机** | 6/6 稳定 **26** |

### 测试

- 全仓 413 → **417**：新增「择强三条分支 + 平手保留先到」以及**「全部 6 种货架排列产出完全相同的目录」**——后者直接锁死「结果不得依赖网关顺序」。
- **变异验证 3 次全部被抓**（改回先到先得 / 去掉 Max 优先 / 平手规则改成后到者胜）。

报告人 **JiewiW** 的定位（跨组容量不一致 + 组顺序不稳定）与实测数据完全正确，并附了可直接套用的补丁思路——本版按其方向实现，并补上了顺序无关性的回归测试。
