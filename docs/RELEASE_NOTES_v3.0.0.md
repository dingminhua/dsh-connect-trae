## v3.0.0（2026-10-07）

> **积分从「侧边栏常驻一行」改为「输入框工具栏的按供应商读数 + 账号表格浮层」。**

这是一次**大版本**，因为它含**一处功能移除**与**一处行为变更**：

- **侧边栏积分行已移除**。它与同族插件 `dsh-connect-workbuddy` 争同一条共享行，实测被挤成裁切的碎片；现在积分只在输入框工具栏出现，且**只在选中的模型属于本插件时**出现——两个连接器插件因此不再抢同一个位置。
- **`showPointsInMainUi` 重新生效**。2.11.0–2.13.2 期间读数无视该字段、始终渲染；现在它重新遵守这个字段（**默认关闭**）。字段已为 `true` 的用户读数保留，不会发现它被悄悄关掉。

> **npm 上的 `latest` 此前是 2.10.0** —— 2.11.0 至 2.14.0 **均未发布**。因此从 npm 升级会一次性拿到下面全部内容。

### 新增

- **输入框工具栏积分读数** —— 在「专家」与模型选择器之间显示 `Trae CN · <数值>`，5 分钟自动刷新，**只在当前会话选中的模型属于本插件时出现**；选其它供应商的模型时整块不渲染。
- **读数整块可点击** —— 弹出锚定浮层（与旁边的「专家」同一套交互），`Esc` 或点击外部关闭。
- **浮层即账号表格** —— 表头「账号 | 通用积分」，**本区域每个账号一行**，**点行即可切换账号**；当前账号标绿点并禁用（避免写入一个没有变化的选值）；手动刷新按钮在浮层内。
- **卡片恢复开关** —— 「在输入框工具栏显示积分读数」，且**只出现在国内版面板**（国际版是订阅制，没有可比余额）。

### 修复

- **切换账号后，另一个账号不再丢失积分**（本版）。根因是凭据副本的合并规则——**桌面副本先入、own 副本同 id 即跳过**，于是插件自己刷新出来的有效凭据被丢弃，账号永远「token 过期」，而有效 token 就在隔壁文件里。现在**按账号归并，同一 id 保留访问 token 更长寿的副本**；插入顺序仍跟随桌面列表，所以「选哪个账号」不变。
- **绑定账号的取数改走会刷新 token 的路径**。它的存储 token 常态是过期的，而 `creditsOfAccount` 是纯查找、按设计原样返回过期 token；表格不排除选中账号，故改用与用量接口同一条路径，并在客户端用用量文档兜底——**同一屏上读数与表格不能对同一账号给出两个答案**。
- **客户端整半无法加载**（2.13.2）：`react-dom` 未外部化而被内联，其开发构建在浏览器读 `process.env` 抛错。现已外部化，并新增静态守卫**禁止把宿主已提供的包打包进来**。
- **composer 整段样式丢失**（2.13.5）：移除侧边栏时连带删掉了 composer 的样式，导致触发器退回浏览器默认按钮方框、浮层因缺 `position: fixed` 而不可见。已拆成独立样式表并由组件自行注入，另加结构守卫。
- **读数字号与颜色**（2.13.6）：由继承正文改为 12px + 浅一级的 `label-tertiary`。
- **与 `dsh-connect-workbuddy` 侧边栏行重叠**（2.10.3）：行容器声明独占整行宽度。

### 测试

- 全仓 **485 例**通过（51 个文件）。本次两处修复均经**变异验证**：改回旧规则立即失败（副本合并 2 例、绑定账号取数路径 4 例、客户端兜底 1 例）。
- 另有一批**结构性守卫**，防的是 jsdom 测不出来的问题：客户端不得打包宿主已提供的包、组件渲染的每个类必须在它注入的样式表里有规则、浮层必须 `position: fixed`。
